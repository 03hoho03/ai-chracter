# packages/ui

- shadcn 컴포넌트는 `components.json` 설정으로 `npx shadcn@latest add <name> -c packages/ui`(또는 이 패키지 안에서 `-c .`)로 추가한다. CLI가 이 패키지 스코프(`@ai-character-chat/ui`)의 alias를 그대로 써서 `src/components/*.tsx`에 생성한다.
- Tailwind는 v4(CSS-first)라 `tailwind.config.js`가 없다. 색상/타이포/spacing/radius 토큰은 전부 `src/styles/globals.css`의 `:root`/`@theme inline` 블록 하나에만 정의한다(DESIGN.md와 동일 소스 유지). 새 앱(`apps/admin` 등)이 이 패키지를 쓰려면 `@tailwindcss/vite` 플러그인만 추가하고 진입점에서 `@ai-character-chat/ui/globals.css`를 import하면 된다.
- `globals.css`의 `@source` 경로는 CSS 파일 실제 위치(`packages/ui/src/styles/`) 기준 상대경로다. 새 앱을 추가할 때 그 앱의 `src`가 이미 `../../../../apps/**/*.{ts,tsx}` 글롭에 걸리는지 확인하고, 걸리지 않으면 새 `@source` 줄을 추가한다.
- 다크모드는 `.dark` 클래스 기반이다: `globals.css`에 `.dark` 토큰 블록과 `@custom-variant dark (&:is(.dark *))`가 정의되어 있어 `html`에 `dark` 클래스를 붙이면 전환된다(`:root`/`.dark`에 `color-scheme`도 선언되어 네이티브 컨트롤·스크롤바가 따라온다). 다크에서 primary·destructive는 밝은 채움 + 어두운 텍스트로 반전된다(밝힌 색 위 흰 텍스트는 AA 미달이라 foreground도 함께 뒤집은 것 — 토큰 조정 시 유지할 것). `sonner.tsx`의 `Toaster`는 `theme` prop을 받는다(기본 `"light"`) — web은 `apps/web/src/app/toaster.tsx`의 `AppToaster`가 현재 테마를 전달하고, admin은 prop 없이 light 고정이다.
- 유채색 토큰을 바꿀 때 **정지 상태 대비만 재면 부족하다** — `button`의 default variant는 hover에서 `bg-primary/80`이라 채움이 배경 쪽으로 20% 옅어진다(Tailwind v4는 이걸 `color-mix(in oklab, ...)`로 컴파일한다). 정지 6.7:1이던 조합이 hover에서 4.77:1까지 떨어지므로 **hover 값까지 4.5:1을 넘는 명도를 골라야 한다.** 브라우저에서 재려면 1×1 canvas에 배경을 칠하고 그 위에 `color-mix(in oklab, <token> 80%, transparent)`를 덧칠해 `getImageData`로 읽는다.
- 유채색 토큰의 chroma는 취향이 아니라 **sRGB 게멋 상한에 걸린다**(hue 0에서 L 0.5 → 최대 C 0.203, L 0.72 → 0.191). 상한을 넘긴 값을 적으면 브라우저가 조용히 클리핑해서 의도한 색이 안 나온다. 새 값을 정할 땐 oklch→linear sRGB로 변환해 세 채널이 0~1 안에 있는지 먼저 확인할 것.
- **`bg-destructive/10 text-destructive` 조합은 `background`(가장 밝은/어두운 끝) 위에서만 AA를 넘긴다.** 평평한 `background` 위 라이트 4.57:1 / 다크 4.58:1로 4.5:1을 아슬아슬하게 넘길 뿐이라 여유가 0.1도 안 되고, 표면이 한 칸만 안쪽으로 들어가도 깨진다.
  - `bg-card` 위(명도 사다리 한 칸): **라이트 4.21:1 / 다크 4.35:1 — 양쪽 다 AA 미달**. 실측 사례는 `apps/web` 로그인 실패 배너와 `apps/admin` 로그인 실패 배너(둘 다 카드 안의 오류 문구).
  - 같은 계열 틴트 위(`bg-destructive/5` 배너 안의 destructive 버튼): 라이트 4.24:1 — `ChatRoomView`의 응답 실패 배너 + "다시 시도"가 실측 사례.
  - 즉 이 틴트를 카드·팝오버·시트 같은 안쪽 표면에 얹으려면 텍스트 대비를 따로 확보해야 한다(문구를 `foreground`로 두고 색은 아이콘·보더에만 쓰거나, 배너 배경을 무채색으로 둘 것). 경고 배너 안에 액션이 필요하면 destructive 버튼을 겹치지 말고 `ghost`/`outline`을 쓴다.
- **dialog/sheet의 enter/exit 애니메이션에는 `prefers-reduced-motion` 게이트가 없다**(`data-open:animate-in ...`이 무조건 걸린다 — `set media reduced-motion`에서도 `animationName: "enter"`로 실측됨). 호출부에서 `className="motion-reduce:animate-none"`으로 끄려 해도 소용없다: `data-open:` 변형이 속성 선택자를 붙여 특이도가 더 높아 진다. 앱 전체에서 이 규칙(DESIGN.md "모든 애니메이션에 motion-safe:")을 지키려면 호출부가 아니라 이 프리미티브들을 함께 고쳐야 한다.
- dialog/sheet/alert-dialog 오버레이의 `bg-black/10`(+`backdrop-blur`) 스크림은 라이트/다크 공통으로 의도된 하드코딩이다(US-131에서 판정 — 다크에서는 블러가 배경 분리를 담당). 하드코딩 색상 정리 시 시맨틱 토큰으로 바꾸지 말 것.
- shadcn 컴포넌트 소스를 그대로 가져오되 `dark:` variant 클래스는 제거했고(토큰 기반이라 대부분 `.dark` 블록만으로 동작), 사용자 노출 텍스트("Close" 등)는 한국어로 교체했다 — 새 컴포넌트를 추가할 때도 동일하게 정리하되, 다크에서 토큰만으로 대비가 안 나오는 경우에만 `dark:` 클래스를 선별 복원한다.
- Toast는 shadcn에서 deprecated된 `toast` 대신 `sonner`를 쓴다. `<Toaster />`는 앱 루트에 한 번만 마운트(`apps/web/src/main.tsx`)하고, 실제 호출은 각 기능 코드에서 `import { toast } from "sonner"`로 직접 한다(패키지 재노출 없음) — 그래서 `sonner`를 쓰는 앱은 자신의 `package.json`에도 `sonner`를 직접 의존성으로 추가해야 한다(pnpm 워크스페이스는 간접 의존성을 자동으로 끌어오지 않음).
- 한글 UI이므로 폰트는 Pretendard(`pretendard` npm 패키지의 variable dynamic-subset)를 쓴다. Fontsource 계열이 아니라 `pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`를 globals.css에서 직접 import한다.
