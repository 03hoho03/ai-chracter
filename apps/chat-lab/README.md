# chat-lab

채팅 엔진 측정 런을 런 목록 → 턴 → 호출 순으로 들여다보는 개발자 도구다. 이 폴더는 그 화면(웹)이고, 런 폴더를 읽어
결합·지표·원가를 내는 쪽은 엔진 옆의 측정 서버(`apps/api/scripts/chat_lab/`)다. 누가 무엇을 하려고 쓰는지와 원칙은 같은 폴더의
`PRODUCT.md`, 비주얼 시스템은 `DESIGN.md` 에 있다. 이 문서는 띄우는 법, 측정 서버가 읽는 런 폴더 형식, 턴 기록 내보내기, 정적
HTML 내보내기, 호스팅 서비스에 올릴 때의 묶음 계약 판과 출처 칸, 서비스에 넣는 웹 빌드(호스팅 모드), 런을 서비스에 올리는 명령,
떼어 갈 때 챙길 것을 다룬다.

## 기동

- **측정 서버**: 띄우는 명령·기본 주소·인자·바인드·DB 규칙은 `DEV.md` 「5) 채팅 측정 도구(chat-lab)」 절에 있다.
- **웹**: 저장소 루트에서 `pnpm --filter chat-lab dev` — `http://127.0.0.1:5291` 에 뜬다. 포트는 고정이고(`strictPort`), 비어
  있지 않으면 다른 포트로 옮기지 않고 바로 실패한다. 측정 서버를 기본 주소가 아닌 곳에 띄웠으면
  `VITE_CHAT_LAB_API=http://127.0.0.1:<포트> pnpm --filter chat-lab dev` 처럼 주소를 바꾼다.
- **둘의 관계**: 웹은 측정 서버를 HTTP 로만 읽는다 — 런 폴더도 DB 도 직접 보지 않는다. 측정 서버의 CORS 는 웹 dev 오리진
  (`127.0.0.1`·`localhost` 의 5291)만 받아서, 웹 포트를 바꾸면 화면은 떠도 요청이 전부 막힌다. 웹 포트는 `vite.config.ts`, 받는
  오리진은 `apps/api/scripts/chat_lab/app.py` 에 따로 적혀 있어 둘을 함께 바꿔야 한다.
- **목록이 바뀌는 때**: 측정 서버는 첫 목록 요청 때 런 루트 전체를 훑고(실데이터에서 수십 초) 그 결과를 들고 있다. 이미 찾은
  묶음은 파일(드라이버 로그·짝 파일·같은 폴더의 기본 짝 이름과 매니페스트)의 수정 시각·크기가 바뀌면 다음 요청에서 그 묶음만
  짝을 다시 골라 다시 잇는다 — 진행 중인 측정이 줄을 덧붙이거나 턴 기록을 내보내도 다시 훑지 않고 반영된다. 새로 생긴 묶음은
  화면의 "새로 훑기"(`GET /runs?refresh=true`)를 눌러야 보인다.
- **그 밖의 웹 명령**: `pnpm --filter chat-lab run typecheck`·`test`·`build`, 그리고 `codegen`. `codegen` 은 생성 타입 둘을
  만든다 — 측정 서버 스키마 `openapi.json` → `src/shared/api/generated.ts`, 호스팅 서비스 스키마 `service-openapi.json` →
  `src/shared/api/service/generated.ts`(뒤엣것만 다시 만들려면 `codegen:service`). 측정 서버의 라우트·응답 모델을 고쳐
  `openapi.json` 을 다시 떨궜거나(`DEV.md` 같은 절) 서비스 스키마를 다시 떨궜으면(`apps/chat-lab-service/README.md` 「로컬 개발」)
  이어서 `codegen` 을 돌려 생성 타입도 함께 커밋한다. chat-lab CI(`.github/workflows/chat-lab.yml`)가 같은 명령으로 둘을 다시
  만들어 보고 커밋본과 다르면 실패한다.

## 런 묶음 형식

측정 서버가 읽는 런 폴더 형식은 이 절 하나에만 적는다. 코드는 `apps/api/scripts/chat_lab/` 의 `bundles.py`(찾기·짝),
`join.py`(결합), `chat_turns_file.py`(턴 기록 파일), `run_id.py`(묶음 id)이고, 이 절과 코드가 다르면 코드가 맞다 — 이 절을 고친다.

### 묶음과 파일

묶음은 드라이버 로그 하나와 그 짝 파일(최대 셋)이다. 모두 JSON Lines(줄마다 JSON 객체 하나)다.

| 파일 | 쓰는 쪽 | 같은 폴더 기본 이름 | 매니페스트 키 |
| --- | --- | --- | --- |
| 드라이버 로그 | 측정 드라이버 `apps/api/scripts/chat_play.py` 의 `--log` | 없음 — 이름이 아니라 내용으로 찾는다 | `chat`(없으면 `chat.jsonl`) |
| 기억 스냅숏 | 같은 드라이버의 `--snapshot-log` | `memory-snapshots.jsonl` | `snapshots` |
| 프롬프트 덤프 | 측정 대상 API 서버(설정 `PROMPT_DUMP_PATH`) | `prompt-dump.jsonl` | `dump` |
| 턴 기록 | 턴 기록 내보내기(아래 절) | `chat-turns.jsonl` | `turns` |

각 파일에서 그 묶음 방(`roomId`)의 줄만 쓴다.

### 드라이버 로그를 찾는 규칙

측정 서버의 런 루트(`--root`) 아래 `*.jsonl` 을 모두 경로 순으로 보고, 아래 셋을 모두 만족하면 드라이버 로그다. 경로의 어느
마디라도 링크면 건너뛰고, 읽지 못하는 파일(권한·사라짐)은 묶음이 아닌 것으로 친다.

1. 빈 줄을 뺀 첫 줄의 `kind` 가 드라이버 줄 종류 — `meta`·`opening`·`login`·`relogin`·`rebase`·`turn`·`pause`·`noteUpdate`·
   `check`·`preCheck`·`regenerate`·`edit` — 가운데 하나다. 훑는 비용 때문에 첫 줄로 먼저 거르고, 통과한 파일만 끝까지 읽는다.
   첫 줄이 `meta` 일 필요는 없다 — 로그인 줄(`login`·`relogin`)이나, 이미 있는 방을 새 로그로 이어 칠 때의 기준 다시 잡기 줄
   (`rebase`)로 시작하는 로그가 있다. 스냅숏(`roomStatic`·`memorySnapshot`)·덤프(`generation`·`judgment`·`background` 이거나
   `kind` 없음)·턴 기록(`export`)은 첫 줄에서 빠진다.
2. 턴 줄(`kind` 가 `turn`)이 하나 이상이다.
3. 줄들에 적힌 `roomId`(문자열) 값이 정확히 하나다. 로그인 줄처럼 `roomId` 칸이 없는 줄은 세지 않는다. 방이 둘 이상이거나
   하나도 없으면 묶음이 아니다.

경로에 `probes` 폴더가 있으면 그 폴더까지의 경로가 묶음의 `group` 이 되고, 목록은 그 키로 대량 시도 폴더를 한 줄로 접는다.

### 형식 세대

턴 줄을 보고 셋으로 가른다(목록의 `format`).

- **현행**(`current`): 턴 줄 가운데 `shortcutId` 나 `assistantMessageId` 가 있는 것이 하나라도 있다. 지금 드라이버는
  `shortcutId` 를 실패한 턴 줄에도 늘 쓰고, `assistantMessageId` 는 응답을 받은 줄에만 쓴다.
- **`assistantMessageId` 이전**(`preMessageId`): 턴 줄마다 `roomId` 는 있는데 위 두 칸이 없다. 열리지만 턴 기록 행을 붙일 응답
  id 가 없어, 턴 기록 파일을 짝으로 두어도 행을 턴에 잇지 않는다. 행마다 짝 없는 행(`unmatchedRow`) 불일치로 세지 않고 그 사실
  하나를 주의(`chatTurnsNotJoined`)로 달며, 붙은 행이 없으니 원가도 내지 않는다(0 원이 아니라 비어 있다). 내보내기도 거부한다
  (아래 「턴 기록 내보내기」).
- **옛 형식**(`legacy`): 턴 줄 가운데 `roomId` 칸이 없는 것이 하나라도 있다. 목록에만 보이고 열지 않는다(상세는 422,
  내보내기는 거부).

방 id 가 uuid 가 아닌 로그도 열지 않는다.

### 짝 파일

- **같은 폴더의 기본 이름이 먼저다.** 드라이버 로그와 같은 폴더에 기본 이름의 일반 파일(링크가 아닌 것)이 있으면 매니페스트와
  상관없이 그것을 쓴다. 매니페스트가 그 키에 다른 값을 적었으면 기본 이름을 썼다는 주의(`manifest`)를 단다.
- **`turns.jsonl` 은 짝이 아니다.** 옛 드라이버가 드라이버 로그를 그 이름으로 썼다 — 짝으로 읽으면 드라이버 로그를 턴 기록으로
  연다. 턴 기록의 기본 이름은 `chat-turns.jsonl` 이다.
- **같은 폴더 밖 파일은 매니페스트로만 잇는다.** 조상 폴더나 런 루트에서 짝을 찾아 붙이는 자동 규칙은 없다. 같은 방을 여러
  묶음이 쓰면(체크포인트 복원·가지치기 측정) 조상 폴더의 덤프를 방 id 로 걸러도 다른 시도의 줄이 섞이기 때문이다. 그래서 같은
  방을 쓰는 묶음이 런 루트에 둘 이상인데 이 묶음이 매니페스트로 같은 폴더 밖 짝을 쓰면 "방 공유" 주의(`roomShared`)를 단다.
  방을 혼자 쓰는 묶음이 폴더 밖 짝을 쓰는 것은 주의가 아니다.

기본 이름이 없을 때 쓰는 매니페스트는 드라이버 로그와 같은 폴더의 `chat-lab.json` 이다.

```json
{
  "chat": "chat.jsonl",
  "snapshots": "memory-snapshots.jsonl",
  "dump": "../dumps/prompt-dump.jsonl",
  "turns": "chat-turns.jsonl"
}
```

- 매니페스트는 그 폴더의 드라이버 로그 하나에만 걸린다 — `chat`(없으면 `chat.jsonl`)이 그 로그의 파일 이름과 같을 때만 읽고,
  다른 로그에는 조용히 쓰지 않는다.
- 값은 묶음 폴더 기준 상대 경로 문자열이다. 빈 값·절대 경로·resolve 한 뒤 런 루트 밖·파일이 아님이면 그 항목을 버리고 주의
  (`manifest`)를 단다. 빠진 키는 짝이 없는 것이다.
- 매니페스트가 JSON 객체로 읽히지 않으면 통째로 버리고, 그 폴더의 묶음에 주의(`manifest`)를 단다.

### 묶음 id

`runId` 는 런 루트 기준 드라이버 로그의 상대 경로(POSIX)를 base64url 로 감싸고 끝의 `=` 를 뗀 문자열이다. 경로의 `/` 가 URL
라우팅을 깨지 않게 한 마디로 감싼 것이고, 웹 주소와 측정 서버 경로에 실린다. 드라이버 로그를 옮기거나 이름을 바꾸면 id 도
바뀐다. 측정 서버는 되돌릴 때 정규형 상대 경로만 받고(`..`·`.`·빈 마디·절대 경로·NUL 거부), 마디에 링크가 있거나 resolve 한
결과가 루트 밖이면 거부한다. 어느 경우든 응답은 "그런 묶음이 없다" 404 다.

### 줄 읽기

드라이버 로그·스냅숏·덤프에 걸리는 규칙이다(턴 기록 파일은 아래 「턴 기록 파일 `chat-turns.jsonl`」의 읽기 규칙을 따른다).

- 파일을 개행으로 나눈 뒤 줄마다 따로 UTF-8 로 디코드한다. 기록 중인 파일은 마지막 줄이 여러 바이트 글자 가운데서 잘릴 수
  있어서, 통째로 디코드하면 그 한 줄 때문에 묶음 전체가 열리지 않는다.
- 파일 끝의 개행 없는 마지막 줄이 읽히지 않으면 기록 중에 잘린 줄로 보고 버린다(`incompleteLine` 주의). 그 밖에 읽지 못한 줄과
  JSON 객체가 아닌 줄은 건너뛴다(`unreadableLine` 주의).

### 덤프 판정

- 덤프 파일은 이름으로 고른다 — 같은 폴더의 `prompt-dump.jsonl` 이나 매니페스트의 `dump`.
- 그 파일 안에서 `roomId` 와 `prompt` 칸이 둘 다 있고 `kind` 가 `generation`·`judgment`·`background` 인 줄만 덤프 줄이다.
  `kind` 칸이 없는 줄은 옛 덤프의 생성 줄로 읽는다. `kind` 만 보지 않는 것은 옛 계측 파일(`trace.jsonl` 등)에도
  `kind: generation` 줄이 있지만 프롬프트가 없어서다. 덤프 꼴이 아닌 줄은 개수와 함께 주의(`notDumpLine`)로 남긴다.
- 덤프 줄이 하나도 없으면(덤프 파일이 없거나, 어느 방의 것이든 꼴이 맞는 줄이 0) 그 묶음은 덤프가 없는 것으로 보고, 생성 덤프 없는 시도를
  불일치로 세지 않는다.

### 턴 기록 파일 `chat-turns.jsonl`

첫 줄은 머리 줄이고 나머지는 행 하나당 한 줄이다.

```json
{"kind": "export", "exportedAt": "<ISO 시각>", "roomId": "<방 uuid>", "scope": "<내보내기 시점 상태라는 문장>", "pricesAsOf": "<단가표 기준일>", "pricesSha256": "<단가표 sha256>", "statDefs": [{"id": "<스탯 id>", "name": "<이름>", "hiddenFromPlayer": false}]}
{"kind": "row", "row": {"<chat_turns 칼럼>": "<값>"}}
```

- **머리 줄**(`kind` 가 `export`): 내보낸 시각, 방 id, 이 파일이 "내보내기 시점 상태"라는 문장(`scope`), 단가표 기준일과 단가표
  내용의 sha256, 방 시작 설정의 스탯 정의(id·이름·숨김 여부).
  - 내보내기 시점 상태: DB 에는 그 방의 마지막 상태만 있어, 같은 방을 이어 친 다른 측정의 행이 섞일 수 있다.
  - 단가표: 원가는 읽는 때 지금 단가표로 다시 낸다. 기준일은 표 전체를 다시 확인한 날이라 그 뒤 줄이 더해져도 그대로여서
    날짜로는 판을 가를 수 없다. 그래서 sha256 이 지금 단가표와 다르면 주의(`pricesChanged`)를 단다.
  - 스탯 정의: 숨김 스탯은 방 스냅숏에 없고 턴 기록에 id 로만 남아, 이 정의가 없으면 이름도 숨김 표시도 보일 수 없다.
- **행 줄**(`kind` 가 `row`): `row` 칸에 `chat_turns` 행 하나를 칼럼 이름 그대로 담고, 값은 uuid·시각만 문자열로 바꾼다. 행을
  한 칸 안에 감싸는 것은 행 자신에도 `kind` 칼럼(send·edit·regenerate)이 있어서다.
- **읽기**: 파일이 UTF-8 로 읽히지 않거나, 첫 줄이 머리 줄이 아니거나, 머리 줄에 칸이 빠졌으면 파일을 쓰지 않고 주의(`unreadableLine`)로 남긴다. 행 줄이 깨졌으면
  그 줄만 건너뛰고 주의로 남긴다. 머리 줄의 `roomId` 가 묶음 방과 다르면 파일째 쓰지 않고 불일치(`chatTurnsRoomMismatch`)로 남긴다.
- 어느 줄도 `kind` 가 `turn` 이 아니고 첫 줄이 `export` 라 묶음을 찾을 때 드라이버 로그로 잡히지 않는다.

### 턴·시도 결합

- **턴과 시도**: 턴은 서로 다른 `clientTurn` 이고, 같은 번호의 턴 줄들은 그 턴의 시도(파일 순서)다. 사람이 친 턴을 나중에
  보충한 줄은 `clientTurn` 이 없어 `roomAfter.turnCount` 를 번호로 쓰고 보충 줄로 표시한다. 둘 다 없는 턴 줄은 불일치
  (`unplacedLine`)다. 첫 번호와 끝 번호 사이에 빠진 번호마다 불일치(`turnGap`)다.
- **DB 응답인 시도**: 생성 리플레이(`apps/api/scripts/replay/logs.py`)가 고르는 줄과 같다 — `roomAfter.turnCount` 가 그 번호인 첫
  턴 줄, 없으면 그 번호의 마지막 턴 줄.
- **생성 덤프**: 그 방·그 턴의 생성 줄(파일 순서) 가운데 마지막 것을 위에서 고른 시도에 붙인다(리플레이가 대조하는 덤프와 같은
  것). 앞선 생성 덤프 k개는 시도별로 가르지 않고 그 턴의 "앞선 생성 덤프"로 둔다 — 연결 오류 시도는 서버에 닿았는지 모르고,
  HTTP 200 이어도 생성 앞에서 끝나면 덤프가 없어서, n번째 시도와 n번째 덤프를 짝지으면 틀릴 수 있다. 고른 시도가 서버 앞에서
  거부된 것(HTTP 비200)이면 덤프가 없는 것이 정상이라 생성 덤프는 모두 앞선 것이다. 고른 시도가 HTTP 200 인데 생성 덤프가
  없으면 불일치(`missingDump`), 그 턴이 없는 생성 줄도 불일치(`unmatchedDumpLine`)다.
- **판정 덤프**: (방, 턴)으로 그 턴에 순서대로 모두 붙인다. 그 턴이 없으면 불일치(`unmatchedDumpLine`)다.
- **백그라운드 덤프**: `turn` 칸이 있으면 그 턴, 없으면 파일 순서상 바로 앞 생성 줄의 턴에 둔다. 어느 쪽이든 배치는 추정이라
  줄마다 주의(`placementEstimated`)를 단다 — 백그라운드 작업은 응답을 보낸 뒤 돌아 다음 턴 생성 줄보다 늦게 쓰일 수 있고, 요약
  접기 줄의 턴 칸은 작업이 읽은 방 턴 수라 다음 턴이 먼저 커밋되면 하나 크다. 놓을 턴이 없으면 불일치(`unmatchedDumpLine`)다.
- **교체 줄**(`regenerate`·`edit`): `clientTurn` 이 없고 대상 턴은 `turnBefore` 다. 그 턴에 "응답 교체됨"으로 붙고 타임라인
  표지가 된다. 그 턴의 응답을 바꾼 것으로 치는 줄은 HTTP 200·완료·빈 응답이 아닌 교체 줄 가운데 마지막 것이다(실패한 교체는
  응답을 바꾸지 않는다). 대상 턴이 없으면 불일치(`unplacedLine`)다.
- **표지 줄**: `rebase`·`check`·`noteUpdate`·`pause` 는 그 줄을 쓸 때까지 마친 턴 수 자리의 타임라인 표지다(`noteUpdate`·`pause` 는
  `turnCount`, 나머지는 `roomAfter`·`accumulated`·`fetched` 의 `turnCount`).
- **턴 기록 행**: 행의 `assistant_message_id` 가 시도의 `assistantMessageId` 와 같은 시도에 붙는다(고른 시도가 아니어도). 맞는
  시도가 없는 행은 불일치(`unmatchedRow`)다. `assistantMessageId` 이전 형식은 잇지 않는다(위 「형식 세대」).
- **보낸 모델과 설정값**(목록 항목과 상세 `run` 의 `sentChatModels`·`sentChatModelsFrom`·`configuredChatModels`): 보낸 모델은
  호출 기록에서 찾는다 — 덤프 생성 줄의 `model`(실제로 보낸 id. 같은 줄의 `chatModel` 은 방이 고른 모델 이름이다)이 먼저고, 덤프에
  생성 줄이 없으면 턴 기록 파일의 행 전부에서 행마다 생성 호출 칸의 모델, 생성 호출이 기록되지 않은 행은 그 행의 `chat_model` 이다.
  시도에 붙지 않은 행과 행을 잇지 않는 `assistantMessageId` 이전 형식의 행도 센다(다른 방의 파일은 위 규칙대로 쓰지 않는다). 원가는
  여전히 붙은 행만 합한다. 방 스냅숏(`roomStatic`)의 `effectiveChatModel` 은 설정값으로 따로 싣는다 — 모델을 바꿔 돌린 런에서는
  보낸 모델과 다르다. 목록 표의 모델 칸은 보낸 모델을 적고, 그것이 없을 때만 설정값을 "설정값"이라고 붙여 적는다.
- **스탯 대조**: 드라이버는 보이는 스탯을 이름 키(`roomAfter.stats`)로, 턴 기록은 id 키(`stat_changes`, 값은 `[전, 후]`)로
  남겨서, 방 스냅숏(`roomStatic`)의 id↔이름 표로 잇고 스냅숏에 없는 스탯은 내보낸 정의(숨김 제외)로 채운다. 스냅숏마다 스탯
  목록이 다르거나 이름이 같은 스탯이 있으면 이름을 id 로 되돌릴 수 없어 대조를 건너뛰고 주의(`statDefsChanged`)를 단다. 고른
  시도의 드라이버 값과 그 시도에 붙은 행의 뒤 값이 다르면 불일치(`statMismatch`)다. 내보낸 정의와 방 스냅숏이 둘 다 있는데
  내보낸 정의(숨김 제외)가 마지막 방 스냅숏의 스탯 목록과 달라도 불일치(`statMismatch`)다. 숨김 스탯은 방 스냅숏에 없어 견주지 않는다(견주면 늘 거짓 불일치가 된다).

조용히 버리는 줄은 없다 — 이 방의 덤프 줄과 턴 기록 행은 모두 어딘가에 붙거나 불일치로 남는다. 예외는 잇지 않는
`assistantMessageId` 이전 형식의 턴 기록 행으로, 그 수를 주의(`chatTurnsNotJoined`) 하나에 적는다.

### 불일치와 주의

위 결과는 두 목록으로 따로 나간다. 둘을 섞지 않는 까닭은 `PRODUCT.md` 「원칙」에 있다.

- **불일치**(`mismatches`, 목록의 불일치 수는 이것만 센다): `missingDump`·`unmatchedRow`·`turnGap`·`statMismatch`·
  `unmatchedDumpLine`·`unplacedLine`·`chatTurnsRoomMismatch`.
- **주의**(`cautions`): `placementEstimated`·`roomShared`·`incompleteLine`·`unreadableLine`·`manifest`·`notDumpLine`·
  `pricesChanged`·`statDefsChanged`·`chatTurnsNotJoined`.

각 종류가 생기는 조건은 위 소절들에 있고, 응답의 `kind` 값 목록은 측정 서버 스키마(`openapi.json`)에 있다.

## 턴 기록 내보내기

턴 기록(`chat_turns`)은 런 당시 로컬 DB 에만 있고 그 DB 볼륨은 대개 지워져서, 묶음 옆에 파일로 옮겨 둔다.

- **쓰는 것**: 그 묶음 방의 `chat_turns` 행 전부(턴 번호·생성 시각·id 순)와 방 시작 설정의 스탯 정의를 읽어, 드라이버 로그와
  같은 폴더의 `chat-turns.jsonl` 로 쓴다(형식은 위 「턴 기록 파일 `chat-turns.jsonl`」). 같은 폴더의 임시 파일에 다 쓴 뒤 이름을
  바꿔, 쓰다 끊겨도 반쯤 쓴 파일이 남지 않는다. 드라이버 로그·스냅숏·덤프는 건드리지 않는다.
- **두 길**: 웹 런 상세의 "턴 기록 내보내기"(측정 서버 `POST /runs/{runId}/export-turns`, 본문 `{"force": <bool>}`)와 명령줄.
  둘이 같은 함수를 부르고 거부 규칙도 같다. 명령·인자·종료 코드는 `DEV.md` 「5) 채팅 측정 도구(chat-lab)」 절에 있다.
- **로컬 DB 만**: 호스트 허용 목록은 `DEV.md` 같은 절에 있다. 거기에 더해 호스트가 없는 주소(유닉스 소켓)도 로컬로 단정할 수
  없어 거부하고, 주소 칸이 로컬이어도 쿼리의 `host`·`hostaddr` 가 하나라도 목록 밖이면 거부한다 — 드라이버는 그 쿼리 값으로
  접속하기 때문이다. 측정 서버는 띄울 때 이 가드를 걸고 DB 엔진은 첫 내보내기나 출처 조회(아래 「묶음 계약 판과 출처 칸」) 요청
  때 하나 만들어 둘이 함께 쓴다(목록·상세·통째 묶음은 DB 에 닿지 않는다). 트랜잭션은 읽기 전용이다.
- **거부**: 파일 시스템 검사를 DB 를 읽기 전에 한다. 괄호는 측정 서버 응답의 `reason` 과 상태 코드다.
  - 옛 형식이거나 방 id 가 uuid 가 아니다(`unsupported`, 422).
  - `assistantMessageId` 이전 형식이다(`unsupportedFormat`, 422). 턴 기록을 응답과 이을 열쇠가 없어 내보내도 이을 수 없고, 파일만
    남으면 묶음이 "턴 기록 있음"으로 보이는데 원가·토큰은 끝내 빈다. 강제여도 쓰지 않는다.
  - 묶음 폴더나 그 조상이 런 루트의 `archive/` 나 저장소의 `apps/api/probe-runs/archive/` 와 같은 폴더다(`archived`, 403). git 이
    추적하는 폴더라 쓰면 대화 원문이 든 파일이 공개 저장소에 커밋될 수 있다. 경로 글자가 아니라 장치·inode 로 같은 폴더인지
    본다 — 대소문자를 가리지 않는 파일 시스템이나 링크로 닿는 경로도 막으려는 것이다.
  - 그 폴더에 서로 다른 방의 드라이버 로그가 있다(`multipleRooms`, 422). 턴 기록 파일 이름은 폴더에 하나라 그 폴더의 모든 로그가
    그 파일을 짝으로 읽는데, 어느 방의 기록을 써야 하는지 정할 수 없다.
  - 파일이 이미 있다(`exists`, 409) — 손으로 고쳤거나 지금 DB 에 없는 행을 담았을 수 있어 되돌릴 수 없다. 강제(`force`)로만
    바꾼다.
  - 그 자리에 링크나 일반 파일이 아닌 것이 있다(`notFile`, 422). 강제여도 쓰지 않는다.
  - DB 에 그 방이 없거나(`noRoom`, 422) 행이 0 이다(`noRows`, 422) — 다른 DB 를 가리킨 것이다. 빈 파일을 남기면 묶음이 "턴 기록
    있음"으로 보이고 다음 시도가 덮어쓰기 거부에 막힌다.
  - 측정 서버에서는 그 밖에 그런 묶음이 없으면 404(`notFound`), DB 가 설정되지 않았거나 DB 접속·파일 쓰기가 실패하면 503(`dbUnavailable`), 본문이
    `application/json` 이 아니면 415(`notJson`)다.

## 정적 HTML 내보내기

런 하나를 측정 서버 없이 `file://` 로 여는 HTML 한 장으로 굳힌다. 웹 빌드(`dist/`)의 JS·CSS 를 문서 안에 넣고, 데이터는 측정
서버의 통째 응답(`GET /runs/{runId}/bundle`) 하나만 `<script type="application/json">` 으로 싣는다. 화면은 그 데이터를 측정 서버
응답 대신 읽으므로 결합·지표를 다시 계산하지 않고, 측정 서버로 보는 화면과 같은 값을 그린다.

- **명령**: 측정 서버를 띄운 채로 저장소 루트에서 `pnpm --filter chat-lab export:static <묶음 폴더|드라이버 로그>`. 웹을 빌드한 뒤
  `scripts/exportStatic.mjs` 를 돌린다. 상대 경로는 명령을 친 자리 기준이다. 빌드가 이미 있으면
  `node apps/chat-lab/scripts/exportStatic.mjs <대상>` 으로 스크립트만 돌려도 된다.
- **Node**: 22.18 이상(22 계열) 또는 23.6 이상 — 타입 벗기기가 기본으로 켜진 판이다. 스크립트가 태그 id 를
  `src/shared/api/staticBundleElement.ts` 에서 직접 읽기 때문이다. 그보다 낮은 판에서는 `ERR_UNKNOWN_FILE_EXTENSION` 오류
  (`Unknown file extension ".ts"`)로 시작도 하지 않는다 — Node 가 `.ts` 파일을 모듈로 읽지 못한다는 뜻이니 Node 를 올린다. 새
  의존성은 없다.
- **대상**: 런 루트 안의 드라이버 로그나 묶음 폴더. 측정 서버의 런 목록에서 그 경로의 묶음을 찾고, 목록에 없으면 한 번 새로
  훑는다. 폴더에 드라이버 로그가 둘 이상이면 고르지 않고 후보를 보인 뒤 멈춘다 — 로그 경로로 다시 준다.
- **인자**:
  - `--raw`: 원문(덤프 줄의 프롬프트·지시문, 기억 스냅숏의 노트·요약 본문, 상세의 방 스냅숏 — 단축어 프롬프트 전문·대화 프로필
    설명이 든다)까지 싣는다. **기본은 원문 제외**다 — 이 저장소는 공개 저장소라, 내보낸 파일이 커밋돼도 프롬프트 원문이 새지 않게
    한다. 대화(사용자 발화·응답)는 어느 쪽이든 실린다.
  - `--force`: 이미 있는 파일을 바꾼다. 없으면 덮지 않는다(손으로 고친 보고서일 수 있다).
  - `--out <파일>`: 쓸 자리. 기본은 드라이버 로그와 같은 폴더의 `<로그 이름>.html`(원문 포함은 `<로그 이름>.raw.html`)이다.
  - `--root <런 루트>`: 기본 `apps/api/probe-runs`. 측정 서버를 다른 `--root` 로 띄웠으면 같은 값을 준다.
  - `--api <주소>`: 측정 서버 주소. 기본 `http://127.0.0.1:8791`.
- **거부**: 출력은 런 루트 안에만 쓴다. 루트 밖, 런 루트의 `archive/`·저장소의 `apps/api/probe-runs/archive/` 아래(장치·inode 로
  같은 폴더인지 본다 — 링크·다른 대소문자로 닿아도 막는다), 없는 폴더, 그 자리의 링크·폴더는 거부한다. 받은 묶음의 방 id 가 대상
  드라이버 로그의 방 id 칸과 다르거나 묶음에 방 id 가 없어도 쓰지 않는다 — 측정 서버와 스크립트의 런 루트가 다르면 같은 상대
  경로가 다른 런을 가리킨다. 쓰기는 같은 폴더의 임시 파일에 다 쓴 뒤 그 자리로 옮긴다. 종료 코드는 0 씀, 1 거부·실패, 2 인자 오류.
- **턴 기록 없이 내보내면** 원가·토큰 칸이 "내보내기 필요"로 남는데 파일을 받은 사람은 그것을 할 수 없다. 그래서 스크립트가 쓰기는
  하되(종료 0) 먼저 턴 기록을 내보낼 명령을 표준 오류로 알린다(이전 형식 런은 내보내도 채워지지 않아 알리지 않는다).
- **다른 곳에 두려면** 쓴 파일을 복사한다. 원문 포함 파일(`.raw.html`)은 공개 저장소에 커밋하지 않는다.
- **연 화면**: 첫 화면이 그 런의 상세다. 런 목록·새로 훑기·턴 기록 내보내기처럼 측정 서버가 있어야 하는 동작은 없고, 헤더의
  내보내기 자리에 "정적 파일 · 원문 제외/포함"이 적힌다. 원문 없이 내보낸 파일의 원문 칸은 그 까닭을 문장으로 보인다.

## 묶음 계약 판과 출처 칸

런 묶음을 팀이 함께 보는 호스팅 서비스(`lab.ddona.site`)에 올리려고, 측정 서버는 통째 응답에 계약 판을 싣고 올리기용 머리를
따로 낸다. 형식은 이 절 하나에만 적는다. 코드는 `apps/api/scripts/chat_lab/` 의 `schemas.py`(`CONTRACT_VERSION`·`UploadHeader`)·
`source_commit.py`(만든 커밋)·`provenance.py`(출처 칸)이고, 이 절과 코드가 다르면 코드가 맞다 — 이 절을 고친다.

- **계약 판(`contractVersion`)**: 통째 응답(`GET /runs/{runId}/bundle`)의 꼭대기 칸이고 지금 `1` 이다. 올려 둔 묶음은 그 뒤에 고친
  웹이 읽으므로, **웹이 읽는 칸을 지우거나 이름·뜻을 바꾸면 판을 올린다**(`schemas.py` 의 `CONTRACT_VERSION`). 칸을 더하는 것만으로는
  올리지 않는다 — 그래서 새 칸을 읽는 웹은 같은 판인데 그 칸이 없는 옛 묶음도 읽어야 한다. 정적 HTML 에 실리는 응답도 같은 것이라
  판을 함께 갖는다. 호스팅 화면은 자기가 읽는 판(`src/shared/api/service/hostedRuns.ts` 의 `CONTRACT_VERSION`)과 다른 판의 묶음을
  열지 않으므로(아래 「호스팅 모드」), 판을 올릴 때 그 값도 같이 올린다 — 두 값을 맞춰 보는 검사는 없다.
- **묶음 바이트**: 서비스는 올라온 묶음의 JSON 바이트 sha256 을 판 키로 쓴다. 그래서 묶음에는 계약 판만 더하고 만든 커밋·출처 칸은
  넣지 않는다 — 넣으면 측정 서버 커밋만 바뀌었거나 출처를 다시 물었을 뿐 내용이 같은 묶음이 새 판이 된다. 같은 커밋·같은 단가표·
  같은 런 루트에서 같은 자리의 묶음은 요청마다 바이트가 같다. 상세의 런 칸(`detail.run`)에 런 루트 기준 경로로 만든 묶음 id·경로가
  들어가므로, 묶음 폴더를 옮기거나(`archive/` 로 보내기 포함) `--root` 를 바꿔 그 경로가 달라지면 묶음 id 도 바뀌어 서비스에서는
  같은 런의 새 판이 아니라 **다른 런**이 된다(서비스 README 「같은 런 식별」). 매니페스트로 같은 폴더 밖 짝을 쓰는 묶음은 런 루트에서
  같은 방을 쓰는 묶음 수가 바뀌면 방 공유 주의(`roomShared`)가 달라져 바이트가 바뀐다 — 경로는 그대로라 같은 런의 새 판이다.
- **올리기 머리**: `POST /runs/{runId}/upload-header`, 본문 `{"exemptEmails": [<이메일>, …]}`, 응답
  `{"sourceCommit": {…}, "provenance": {…}}`. 출처 칸은 요청할 때만 계산하므로 목록·상세·통째 묶음·정적 내보내기는 그대로 DB 없이
  돈다.
- **만든 커밋(`sourceCommit`)**: `commit` 은 측정 서버 checkout 의 커밋 id(`git rev-parse HEAD`), `dirty` 는 추적하는 파일에
  커밋하지 않은 변경이 있는가(`git status --porcelain --untracked-files=no` 가 비지 않았는가)다. 추적하지 않는 파일은 세지 않는다 —
  checkout 에는 스크린숏 같은 추적하지 않는 파일이 늘 있어 세면 거의 모든 묶음이 더럽다고 나온다. **띄울 때 한 번 읽는다** — 서버가
  낸 묶음은 띄울 때 메모리에 올라간 코드로 만들어지므로 그 커밋이 맞다. 띄운 뒤 checkout 을 옮겼으면 서버를 다시 띄운다. 띄울 때
  git 으로 읽지 못했으면 서버는 그대로 뜨고 올리기 머리만 503(`gitUnavailable`)이다.
- **출처 칸(`provenance`)**: 이 런이 로컬 측정 서버에서 테스트 계정으로만 돈 것인지. 불·수만 싣고 이메일은 싣지 않는다 — 서비스로
  가는 개인정보를 줄인다. 테스트 계정은 이메일이 `@example.com` 으로 끝나는 계정이다(대소문자 무시, 시드 계정
  `seed-creator@example.com`·`test@example.com` 도 이 도메인).

  | 칸 | 뜻 |
  |---|---|
  | `passed` | 아래 `baseLocal` 이 `false` 가 아니고, 방 주인이 테스트 계정이고, `outsideUsers` 가 0 이다. 작가는 넣지 않는다 |
  | `baseLocal` | 드라이버가 meta 줄에 적은 주소(`base`)의 호스트가 `127.0.0.1`·`localhost`·`::1` 인가 — 로컬 DB 가드와 같은 셋이다. 테스트 클라이언트 주소(`testserver`)는 테스트가 만든 합성 묶음이라 받지 않는다. meta 줄이 없는 묶음(프로브 묶음, 이미 있는 방을 새 로그로 이어 친 로그)은 `null`(판정 없음), meta 줄은 있는데 주소 칸이 없거나 문자열이 아니면 `false` |
  | `roomFound` | 묶음의 방이 이 DB 에 있다. 없으면 다른 DB 에서 돈 런이다 |
  | `ownerInExampleDomain` | 방 주인이 테스트 계정이다. 방이 없으면 `false` |
  | `outsideUsers` | 탈퇴하지 않은(`deleted_at` 이 빈) 사용자 가운데 테스트 계정 밖 수 — 실제 회원이 든 DB 일 수 있어서다. 예외로 뺀 사용자는 세지 않고, 정지 회원은 센다 |
  | `exemptedUsers` | `outsideUsers` 에 들었을 사용자 가운데 예외 이메일로 뺀 수 — DB 에 없는 주소, 탈퇴 회원, 테스트 계정 주소는 세지 않는다 |
  | `authorInExampleDomain` | 그 방 작품의 작가가 테스트 계정인가. `false` 는 경고다 — 실제 회원의 작품을 테스트 계정으로 플레이한 런은 올릴 수 있지만 알고 올린다. 방이 없으면 `null` |
- **예외 이메일**: 로컬에서 실제 구글 로그인을 써 본 계정처럼 테스트 계정 밖이지만 무엇인지 아는 사용자를 `outsideUsers` 에서
  뺀다(앞뒤 공백을 떼고 대소문자 무시). 주소창·접속 기록에 남지 않게 요청 본문으로 받는다. 방 주인 판정은 넘기지 못한다.
- **DB 하나**: 출처는 측정 서버가 띄울 때 받은 로컬 DB 주소 하나로 조회한다(위 「턴 기록 내보내기」의 로컬 DB 가드를 통과한 주소,
  읽기 전용 트랜잭션). 런을 돈 DB 가 여럿일 때 띄우는 법은 `DEV.md` 「5) 채팅 측정 도구(chat-lab)」 절.
- **칸이 적은 DB**: 출처 조회는 판정에 쓰는 칸(방의 id·주인·작품, 작품의 id·작가, 사용자의 id·이메일·탈퇴 시각)만 이름으로
  고른다 — 복원한 옛 덤프처럼 지금 모델보다 칸이 적은 DB 에서도 돈다.
- **거부**: 괄호는 측정 서버 응답의 `reason` 과 상태 코드다. 출처 판정이 실패한 것은 거부가 아니라 200 에 `passed: false` 다.
  - 그런 묶음이 없다(`notFound`, 404).
  - 옛 형식이거나 방 id 가 uuid 가 아니다(`unsupported`, 422). 묶음을 열다 실패했다(`openFailed`, 422).
  - 본문이 `application/json` 이 아니다(`notJson`, 415).
  - DB 가 설정되지 않았거나 닿지 않는다(`dbUnavailable`, 503) — 틀린 계정·DB 이름도 여기다. 상세 글에는 예외 이름만 싣는다. 턴
    기록 내보내기의 503 도 같다.
  - 띄울 때 git 으로 커밋을 읽지 못했다 — git 이 없거나 checkout 이 아니다(`gitUnavailable`, 503).
  - 본문 모양이 틀리면 FastAPI 요청 검증 422 다(`reason` 없음, `detail` 이 목록). 측정 서버는 그 항목에 어디가 왜 틀렸는지
    (`loc`·`msg`·`type`)만 싣고 받은 값(`input`)·검증 맥락(`ctx`)은 뺀다. 경로 모두 같다.
- **다시 보는 곳**: 업로드 CLI 가 보내기 전에 드라이버 로그의 meta 줄로 출처를 다시 보고(아래 「올리기」), 호스팅 서비스는 받을 때
  계약 판과 올리기 머리를 다시 보고 머리가 없거나 출처 칸이 실패면 받지 않는다. 받은 계약 판을 읽을 수 있는지는 웹이 판정한다.

## 호스팅 모드

같은 웹을 호스팅 서비스(`apps/chat-lab-service`)에 넣어, 서비스에 올라온 런을 팀이 브라우저로 본다. 서비스 쪽(라우트·신원·판
규칙·배포)은 `apps/chat-lab-service/README.md` 에 있다.

- **켜는 법**: 빌드할 때 환경 변수 `VITE_CHAT_LAB_MODE=hosted` 하나로만 켠다.

  ```sh
  VITE_CHAT_LAB_MODE=hosted pnpm --filter chat-lab run build   # → apps/chat-lab/dist
  ```

  값이 없으면 지금까지처럼 측정 서버를 읽는 로컬 빌드다(`dev` 도 그대로). 그 밖의 값이면 `vite.config.ts` 가 빌드도 dev 서버도
  시작하지 않는다 — `hostd` 같은 오타가 조용히 로컬 빌드가 되지 않게 한다. 상수를 빠뜨린 로컬 빌드가 서비스에 실려도 보는 사람
  컴퓨터의 측정 서버를 부르지 않는다 — 로컬 빌드는 루프백 밖 출처(http(s) 호스트가 `localhost`·`127.0.0.1`·`[::1]` 이 아님)에서
  열리면 측정 서버 요청을 보내지 않고 "이 화면은 로컬 빌드다" 안내(호스팅 빌드로 다시 만들라는 문장)를 띄운다. 정적 묶음이 실린
  문서(정적 HTML)는 빌드와 상관없이 정적으로 돈다. 모드와 출처를 판정하는 곳은 `src/shared/api/labMode.ts` 하나다. 이 빌드를 이미지에 넣어 VM 에 올리는 절차는 서비스 README
  「4. 이미지 만들기·옮기기(운영자 Mac → VM)」에 있다.
- **읽는 곳**: 화면을 내준 같은 출처의 서비스다. 런 목록은 `GET /api/runs`, 런을 열면 목록에 적힌 그 런의 최신 판 묶음
  (`GET /api/runs/{runId}/versions/{sha256}/bundle`) 하나를 받아 상세·턴·지표를 정적 HTML 과 같은 함수로 그 묶음에서 읽는다 —
  측정 서버의 통째 응답을 그대로 올린 것이라 결합·지표를 다시 계산하지 않는다. 턴을 옮겨도 목록과 묶음은 한 번씩만 받고, 다른 런을
  열면 앞 런의 묶음은 메모리에서 버린다. 서비스 응답은 칸을 읽기 전에 겉모양을 본다 — 웹과 서비스가 다른 커밋에서 나왔을 수 있어,
  틀린 칸을 읽어 화면이 깨지는 대신 아래 "응답 꼴 틀림" 안내로 끝낸다. 서비스 응답 타입은 생성 타입
  `src/shared/api/service/generated.ts` 다(만드는 명령은 「기동」).
- **측정 서버에는 닿지 않는다**: 측정 서버로 가는 요청은 나가기 전에 막는다(`src/shared/api/client.ts`) — 나가면 보는 사람 브라우저의
  `127.0.0.1` 로 간다. 그래서 측정 서버가 있어야 하는 동작은 그리지 않는다.
  - 목록 머리·빈 런 루트 안내의 "새로 훑기" → 목록 머리의 "다시 받기"(아래)와, 서비스에 런이 없을 때의 안내.
  - 상세 머리의 턴 기록 (다시) 내보내기·"내보내기 없음 · 이전 형식"·내보내기 결과 안내 → 원문 칩 · 판 번호 · "지우기".
  - 측정 서버 연결 실패 안내(띄우는 명령) → 서비스 실패 안내(아래 표).
  - 원문 칸의 "원문 제외" 문장은 다시 내보내라는 대신 올린 사람이 원문 포함(`--raw`)으로 다시 올리라고 적는다.
  - 빵부스러기의 `런` 은 정적 HTML 과 달리 목록으로 가는 링크다(목록이 있다).
- **계약 판**: 런의 최신 판 계약 판이 이 웹의 판(위 「묶음 계약 판과 출처 칸」)과 다르면 열지 않는다. 목록에서는 그 런을 표에서 빼 런
  표 칸 맨 위의 접힌 띠 "이 웹이 읽지 못하는 런 N개"에 두고 — 목록 칸(`run`)이 측정 서버 목록 한 줄 꼴이 아닌 런도 여기다 — 펼치면
  런마다 런 id·올린 때·원문 칩·까닭과 "지우기…" 가 선다. 숨기지 않는 것은 열 수 없어도 지울 수 있어야 해서다. 계약 판이 다른 런을
  주소로 열면 아래 계약 판 안내가 선다(목록 칸 꼴만 틀린 런은 묶음이 맞으면 열린다).
- **목록이 바뀌는 때**: 처음 받을 때, 목록 머리의 "다시 받기", 지우기(지운 런만 목록에서 뺀다), 아래 지우기 직전 확인(그 런 줄만 새
  값으로 바꾼다)뿐이다. 창으로 돌아오거나 네트워크가
  다시 붙거나 시간이 지나도 저절로 다시 받지 않는다 — 다시 받으면 런의 최신 판이 바뀔 수 있어, 이미 열어 둔 상세(옛 판)와 새로 고른
  턴(새 판)이 한 화면에 섞인다. 그래서 "다시 받기"는 열어 둔 상세·턴·지표와 받아 둔 묶음을 함께 버리고 목록을 새로 받는다. 받기에
  실패해도 저절로 다시 시도하지 않는다(세션이 끝났거나 허용 밖이면 기다려도 같다). 목록 머리에는 런 수와 받은 때가 적힌다 — 지우기와
  아래 지우기 직전 확인은 받은 때를 바꾸지 않는다(나머지 런은 여전히 그때 받은 것이다).
- **원문 칩**: 원문 포함(`--raw`)으로 올린 판에 붙는다. 모양과 자리는 `DESIGN.md` 「Chips」의 원문 칩.
- **판 칸**: 미리보기 맨 아래에 고른 런의 최신 판 — 판 번호와 살아 있는 판 수, 올린 때, 올린 이, 묶음을 만든 측정 서버 커밋(커밋 안
  한 변경이 있었으면 그 표시), 원문 포함·제외, 압축·푼 크기, 계약 판, 작가가 테스트 계정 밖이면 그 줄 — 과 "런 지우기…".
- **지우기**: 미리보기의 "런 지우기…", 상세 머리의 "지우기", 읽지 못하는 런 띠의 "지우기…" 가 확인 대화를 연다. 서비스의 지우기는
  최신 판 하나가 아니라 그 런의 모든 판이고 서비스에는 백업이 없어서(서비스 README 「지우기」·「백업 없음 — 복구는 다시 올리기」),
  대화의 제목과 위험 버튼에 지울 판 수를 적는다.
  - **지우기 직전 확인**: 목록은 저절로 다시 받지 않아, 대화를 연 사이 같은 런에 새 판(원문 포함일 수 있다)이 올라오면 대화는 옛 판
    수를 보이는데 서비스는 지금 살아 있는 판을 모두 지운다. 그래서 누르면 먼저 목록을 캐시를 거치지 않고 새로 받아, 그 런의 최신 판
    sha256·판 수·원문 여부가 대화가 보인 값과 같을 때만 지운다(`src/features/delete-run/api/deleteRunIfUnchanged.ts`). 다르면 지우지
    않고 목록 캐시의 그 런 줄만 새 값으로 바꾼다 — 대화가 새 판 수로 다시 그려지고 대화 안에 "그 사이 새 판이 올라왔다" 한 줄이 서서,
    다시 보고 누른다(상세에서 연 대화면 상세도 새 판으로 다시 받는다). 새 목록에 그 런이 없으면 이미 지워진 것으로 정리하고, 그 목록
    요청이 404 면 허용 밖 신원이라 대화 안에 그 까닭을 남긴다. 남는 틈은 새로 받기와 지우기 요청 사이의 밀리초뿐이다 — 서비스의
    지우기는 판을 가려 받지 않고 그때 살아 있는 판을 모두 지운다.
  - 지우면 목록 머리에 서비스가 센 지운 판 수("지웠다 · 판 3개")가, 누가 먼저 지웠으면 "이미 지워진 런이다" 가 서고, 상세에서
    지웠으면 목록으로 옮긴다. 실패는 대화 안에 한 줄로 남고 다시 누를 수 있다. 대화 안 문장의 원문은
    `src/features/delete-run/model/deleteCopy.ts`, 대화의 모양·포커스·키는 `DESIGN.md` 「Confirm Dialog」.
- **받지 못했을 때**: 본문 자리에 안내가 선다. 갈래는 `src/shared/api/service/hostedFailure.ts` 가 가르고, 문장 원문은
  `src/shared/ui/HostedFailureNotice.tsx` 에만 두고, 아래 표의 제목은 그 사본이다 — 제목을 고치면 표도 고친다. 마지막 줄은 호스팅
  빌드가 아니라 로컬 빌드가 실렸을 때의 안내다(`src/shared/ui/LocalBuildElsewhereNotice.tsx`, 위 켜는 법 항목).

  | 갈래 | 언제 | 제목 | 행동 |
  |---|---|---|---|
  | 세션 끝 | 응답 없음(Access 로그인이 끝나 다른 출처의 로그인 화면으로 넘겨진 요청과 네트워크 끊김이 같은 모양이다)·401·403. 서비스는 403 을 쓰지 않아 403 이면 Access 가 막았다는 줄을 더한다 | 서비스에 닿지 못했다 | 새로고침 — 다시 받아도 같고, 문서를 새로 열어야 Access 가 로그인 화면으로 보낸다 |
  | 허용 밖 | 목록 경로의 404 — 목록 경로는 늘 있으므로 허용 목록 밖 신원이다 | 이 계정으로는 런 목록을 볼 수 없다 | 새로고침, 로그아웃(`/cdn-cgi/access/logout`) |
  | 서비스 오류 | 서비스가 까닭(`reason`·`detail`)을 말한 거부 — 문장을 고치지 않고 그대로 보인다 | 런 목록을 받지 못했다 / 런을 받지 못했다 | 다시 시도 |
  | 응답하지 않음 | 서비스 거부 꼴이 아닌 5xx — 서비스나 그 앞단이 내려갔다 | 서비스가 지금 응답하지 않는다 | 다시 시도 |
  | 응답 꼴 틀림 | 이 웹이 아는 꼴이 아닌 응답 | 서비스 응답이 이 웹이 아는 꼴이 아니다 | 다시 시도. 서비스 이미지를 웹과 같은 커밋으로 다시 만든다 |
  | 계약 판 다름 | 상세를 연 런의 계약 판이 이 웹과 다르다. 새 판이면 웹을 다시 배포하고, 옛 판이면 원본 런을 지금의 측정 서버로 다시 올린다 | 이 판은 이 웹이 읽지 못한다 | 런 목록으로 |
  | 상세 없음 | 묶음 요청의 404, 목록에 없는 런 — 누가 지웠거나 주소의 런 id 가 옛 것이다(지우기의 404 는 이미 지워진 것으로 정리하고 대화를 닫는다) | 이 런이 서비스에 없다 | 런 목록으로 |
  | 측정 서버 요청 | 측정 서버가 있어야 하는 요청이 나가려 했다(위에서 막은 것) | 측정 서버가 있어야 하는 동작이다 | 런 목록으로 |
  | 로컬 빌드가 실림 | 로컬 빌드가 루프백 밖 출처에서 열려 측정 서버 요청을 막았다 — 그 호스트 이름을 적는다 | 이 화면은 로컬 빌드다 | 없음(다시 해도 같다). 호스팅 빌드로 다시 만든다 |

## 올리기

런 하나의 통째 묶음을 호스팅 서비스에 판으로 올린다. 측정 서버를 띄운 채로 저장소 루트에서:

```sh
pnpm --filter chat-lab run upload <묶음 폴더|드라이버 로그> [--raw] [--exempt-email <주소>]…
```

**자격 파일을 읽는 명령(올리기·읽기 시험)은 운영자가 자기 터미널에서 돌린다.** 스크립트는 `scripts/uploadRun.mjs`(흐름은
`scripts/uploadFlow.mjs`)이고 `.ts` 를 읽지 않아 정적 HTML 내보내기의 Node 판 조건이 없다. 새 의존성도 없다.

- **인자**:

  | 인자 | 기본 | 뜻·제약 |
  |---|---|---|
  | `<대상>` | 없음 — 하나만 | 런 루트 안의 드라이버 로그나 묶음 폴더. 상대 경로는 명령을 친 자리 기준. 측정 서버 목록에 없으면 한 번 새로 훑고, 폴더에 드라이버 로그가 여럿이면 후보를 보이고 멈춘다(정적 HTML 내보내기와 같은 규칙) |
  | `--raw` | 끔 | 원문까지 싣는다(범위는 정적 HTML 내보내기의 `--raw` 와 같다). 켜면 팀 모두가 원문을 본다는 경고를 먼저 찍는다 |
  | `--exempt-email <주소>` | 없음 | 출처 칸의 예외 이메일(위 「묶음 계약 판과 출처 칸」). 여러 번 준다 |
  | `--root <런 루트>` | `apps/api/probe-runs` | 측정 서버를 띄운 `--root` 와 같은 값 |
  | `--api <주소>` | `http://127.0.0.1:8791` | 측정 서버. 호스트가 루프백(`127.0.0.1`·`localhost`·`::1`)이 아니면 인자 오류 |
  | `--service <주소>` | `https://lab.ddona.site` | 호스팅 서비스. 기본 서비스 호스트(`https` 만)와 로컬 검증용 루프백 호스트(`http` 도)만 받는다. 그 밖 호스트는 인자 오류이고 요청을 하나도 보내지 않는다 — 오타로 서비스 토큰이 다른 호스트로 나가지 않게, `http` 로 평문이 나가지 않게. 주소에 아이디·비밀번호를 넣어도 인자 오류 |
  | `--credentials <파일>` | `~/.config/chat-lab/service-token.json` | 자격 파일 자리(값이 아니라 자리) |
  | `--read-test` | 끔 | 읽기 시험(아래). 대상·`--raw`·`--exempt-email`·`--root`·`--api` 와 함께 주면 인자 오류 |

- **토큰은 자격 파일로만**: 토큰 값을 받는 인자는 없고(모르는 인자는 인자 오류다), 환경 변수도 읽지 않는다 — `pnpm` 이 넣는 명령
  자리 `INIT_CWD` 만 경로 기준으로 쓴다. 셸에 토큰을 담은 변수가 있어도 쓰지 않는다. 값은 서비스로 가는 머리 두 개
  (`CF-Access-Client-Id`·`CF-Access-Client-Secret`)에만 싣고 어떤 출력·오류·기록에도 넣지 않는다(Client ID 도 찍지 않는다).
- **자격 파일**: JSON 객체 하나에 칸은 정확히 둘 — `{"clientId": "<Client ID>", "clientSecret": "<Client Secret>"}`(모르는 칸·빠진
  칸 거부). 값은 각각 1~512자의 보이는 ASCII 다(공백·줄바꿈 없음). 이 사용자 소유의 일반 파일이어야 하고(링크는 거부 — 실제 자리를
  `--credentials` 로 준다), 하드링크로 이름이 둘 이상 걸려 있으면 거부하고(다른 이름이 아래 저장소 검사가 보지 못하는 자리에 있을 수
  있다), 권한은 정확히 `0600`(`0400` 도 거부), 크기는 4KiB 이하, 링크를 따라간 실제 자리는 git 저장소 밖이어야 한다(`~/.config` 를
  dotfiles 저장소로 링크해 둔 경우도 막는다 — 그 저장소가 공개면 비밀이 커밋된다). 하나라도 어기면 측정 서버·서비스에 묻기 전에
  멈춘다. 값은 서비스 토큰을 만들 때 대시보드가 한 번 보여 준다(서비스 README 「1. 대시보드 쪽(사람)」). 만드는
  명령:

  ```sh
  mkdir -p ~/.config/chat-lab && chmod 700 ~/.config/chat-lab
  install -m 600 /dev/null ~/.config/chat-lab/service-token.json
  # 편집기로 열어 {"clientId": "…", "clientSecret": "…"} 를 적는다 — 값을 채팅이나 셸 명령에 붙이지 않는다(셸 기록에 남는다)
  ```

- **`.git` 없는 저장소는 알아보지 못한다**: 자격 파일과 올리기 기록 자리의 git 저장소 검사는 조상 폴더의 `.git` 으로만 저장소를
  알아본다. `.git` 없이 홈을 작업 트리로 쓰는 dotfiles 저장소(yadm, `git --git-dir=… --work-tree=$HOME` 꼴)는 알아보지 못해 검사가
  걸리지 않는다. 그런 저장소를 쓰면 자격 파일·런 루트가 그 작업 트리 안에 있을 때 그 저장소가 자격 파일·기록 파일을 추적하지 않는지
  직접 확인한다(`yadm status`·`yadm check-ignore <자리>`).

- **흐름**(앞 단계가 실패하면 뒤는 돌지 않는다):
  1. 인자·주소 꼴 → 자격 파일(읽기 시험은 여기서 시험하고 끝난다) → 대상(런 루트 안) → 올리기 기록 자리(아래). 서비스에 올린 뒤
     기록에 못 쓰는 일을 줄이려고 기록 자리를 측정 서버에 묻기 전에 본다.
  2. 측정 서버의 묶음 바이트(`GET /runs/{runId}/bundle?raw=…`)를 받은 그대로 쓴다 — 다시 직렬화하지 않아 sha256 이 측정 서버가 낸
     바이트의 것이다. 받은 묶음의 런 id, 방(대상 드라이버 로그의 방과), 원문 여부(`--raw` 와), 계약 판(1 이상 정수)을 본다.
  3. 올리기 머리(`POST /runs/{runId}/upload-header`)를 받아 **출처를 다시 본다**. 드라이버 로그의 첫 `meta` 줄 주소가 루프백이 아니면
     멈추고, 측정 서버의 `provenance.passed` 가 참이고 로그로 본 루프백 판정이 측정 서버의 `baseLocal` 과 같을 때만 올린다. 둘이
     어긋나면 — 같은 주소를 Node 와 Python 이 다르게 풀었거나, 측정 서버가 다른 `--root` 의 로그를 봤다 — 닫는 쪽으로 간다. 실패
     문구는 막은 칸(방이 이 DB 에 없음, 방 주인, 테스트 계정 밖 사용자 수 …)을 적는다.
  4. 경고만 하고 잇는다: 작가가 테스트 계정 밖, 커밋하지 않은 변경이 있는 측정 서버가 만든 묶음, 턴 기록 파일이 없어 원가·토큰이 빈
     판(턴 기록 내보내기 명령을 함께 찍는다).
  5. 푼 크기가 32MiB, gzip 압축 크기가 8MiB 를 넘으면 멈춘다. 서비스 상한과 같은 값이고 같은 크기는 받는다.
  6. 서비스에 `POST /api/runs/{runId}/versions`(본문 gzip, 올리기 머리는 `X-Lab-Upload-Header` 한 줄)로 보낸다. 넘김(3xx)은 따라가지
     않는다 — 따라가면 자격 머리가 넘긴 곳으로 다시 나간다.
  7. 2xx JSON 이고 돌려준 런 id·sha256 이 올린 것과 같을 때만 올리기 기록에 한 줄을 쓰고 끝난다.
- **서비스 응답**:
  - 성공은 "올렸다 — 판 N(새 판) …"·"이미 있다 — 같은 내용의 판 N …"·"되살렸다 — 지웠던 판을 이번 올리기로 다시 살렸다 · 판 N ·
    sha256 …" 셋이다(판 규칙은 서비스 README 「런과 판」).
  - 3xx("서비스가 넘겼다(<상태>) …")·401·403("Access 가 서비스 토큰을 거부했다(<상태>) …"): Access 가 서비스 토큰을 받지 않았다 —
    토큰이 만료됐거나 자격 파일의 Client ID·Secret 이 틀렸을 수 있고, 토큰을 새로 만들었으면 Access 앱 Service Auth 정책이 새 토큰을
    고르는지도 본다(서비스 README 「운영 노트」). 넘긴 주소는 찍지 않는다.
  - 404: 서비스가 그 토큰의 올리기를 받지 않았다 — 토큰의 Client ID 가 서비스의 올리기 허용 목록(설정 `LAB_UPLOAD_CLIENT_IDS`)에
    있는지 본다.
  - 413·422·503 은 서비스의 `reason`·`detail` 을 그대로 적는다. 그 밖 상태(500 `internal`·405 …)는
    "서비스가 실패했다(<상태>, <reason>)" 로 끝난다(`detail` 은 싣지 않는다). 응답이 없으면 연결 오류 코드만 적는다(오류 문구는
    잇지 않는다).
  - 2xx 인데 JSON 이 아니거나 돌려준 런 id·sha256 이 다르면 기록하지 않고 실패다.
- **올리기 기록**: 올릴 때마다 `<런 루트>/.chat-lab-uploads.jsonl` 에 JSON 한 줄을 덧붙인다. 칸은 `at`(시각)·`service`(올린 서비스
  주소 — 로컬 검증 기록과 운영 기록을 가른다)·`runId`·`target`(런 루트 기준 드라이버 로그 경로, POSIX)·`raw`·`sha256`·`status`
  (`created`·`exists`·`restored`)·`versionNumber`·`compressedSize`·`uncompressedSize` 다. 서비스 DB 를 잃으면 이 목록의 `target` 을
  같은 원문 여부로 다시 올린다 — `pnpm --filter chat-lab run upload <런 루트>/<target>`(`raw` 가 참이면 `--raw`, 기본 런 루트가
  아니면 같은 `--root`). 처음에 `--exempt-email` 로 통과시킨 런은 같은 주소를 다시 준다(주소는 기록에 남기지 않는다). 다시 올려도
  되살지 않는 것은 서비스 README 「백업 없음 — 복구는 다시 올리기」에 있다.
  - 기록에는 런 id·경로·sha256 이 들어 커밋되지 않게 한다. 루트 `.gitignore` 가 `.chat-lab-uploads.jsonl` 을 이름으로 어디서나
    무시한다. 런 루트가 git 작업 트리 안이면(조상 폴더에 `.git` 이 있으면) `git check-ignore` 로 그 저장소가 기록 파일을 무시하는지
    묻고, 무시하지 않으면(이미 추적 중인 파일 포함)·git 이 없거나 답하지 못하면 측정 서버에 묻기 전에 거부한다.
  - 줄에 `kind` 칸이 없어 측정 서버가 묶음으로 잡지 않는다(위 「드라이버 로그를 찾는 규칙」).
  - 런 루트가 저장소의 보관 폴더(`apps/api/probe-runs/archive/`)이거나 그 아래면 올리기 전체를 거부한다 — git 이 추적하는 폴더라
    기록을 쓰지 않는다. 장치·inode 로 같은 폴더인지 본다. 그 자리에 링크·폴더처럼 일반 파일이 아닌 것이 있어도 거부한다.
  - 대상이 보관 폴더 아래인 런은 막지 않는다(읽기만 한다). 보관 폴더로 옮긴 런이 서비스에서 무엇이 되는지는 위
    「묶음 계약 판과 출처 칸」의 묶음 바이트 항목.
  - 서비스에는 올랐는데 기록을 쓰지 못하면 실패로 끝나며 판 번호와 sha256 앞부분을 찍는다. 같은 명령을 다시 돌리면 서비스가 "이미
    있다" 로 답하고 그때 기록이 남는다.
- **종료 코드**: `0` 올렸고(새 판·이미 있음·되살림) 기록을 남겼다, 또는 읽기 시험이 상태 코드를 받았다. `1` 거부·실패 — 대상·자격
  파일·기록 자리·측정 서버·묶음·출처·크기·서비스 응답·기록 쓰기, 그리고 예상하지 못한 오류(오류 이름과 코드만 찍는다). `2` 인자 오류 —
  모르는 인자, 대상 수, 읽기 시험에 올리기 인자를 함께 줌, `--api`·`--service` 주소 규칙.
- **읽기 시험**: `pnpm --filter chat-lab run upload --read-test [--service <주소>] [--credentials <파일>]`. 같은 자격 파일로
  `GET /api/runs` 하나를 넘김을 따라가지 않고 보내 "읽기 시험: GET /api/runs → <상태>" 만 찍는다(본문은 읽어 버린다). 서비스 토큰은
  사람 경로에서 404 를 받는 것이 정상이다 — 토큰이 Access 를 지났고 서비스가 읽기를 막았다는 뜻이다(서비스 README
  「라우트와 상태 코드」). CLI 는 판정하지 않고 사람이 본다. 시험용 비밀 사본을 하나 더 만들지 않고 실제 자격 파일로 "이 토큰으로는
  읽을 수 없다" 를 보려는 모드다.

## 기록 한계

측정 기록에 없어 보여 줄 수 없는 값(판정 응답 원문 등)은 측정 서버가 턴 상세 응답의 `recordLimits` 에 자리(`slot`)와 문장(`text`)
으로 준다. 화면은 그 문장을 그대로 쓴다(까닭은 `PRODUCT.md` 「원칙」, 모양은 `DESIGN.md` 「Record Limit Note (Signature)」).
문장의 원문은 측정 서버 코드에만 두고 여기에 옮기지 않는다.
